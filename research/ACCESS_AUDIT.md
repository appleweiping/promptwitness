# G0 data-access record

No final-test model responses or scores have been generated by this research,
and no final-test results have been read or supplied as optimization feedback.
The completed 400 requests and bounded cost supplement use training-side inputs.
Their outputs must not
be represented as method results or used to pick favorable confirmatory data.

A later, explicit cost-context audit scores only the four preselected
predictor-fit-reserved instruction responses against their training constraints.
Two pass all checks. This checks whether the earlier stress-demo inputs resemble
accepted native demonstrations, not method effectiveness; it neither selects
final units nor changes any task requirement. The inference records remain
immutable: their original `scoring_executed=false` describes that earlier event.

The later fit-context audit checks all 16 previously frozen Qwen base-profile
instruction responses whose IDs are in the fit pool. It records every check in
a fixed hash order; seven pass, and the first four passing responses are each
used once for the bounded native-context cost fixture. The v2 audit fixes the
language detector seed at 11. This is an explicit training-side acceptance check,
not a reproduction of the native bootstrap shuffle, teacher, or optimization gain.

The separately frozen `native-context-v1` calibration uses search-pool original
inputs selected by metadata/hash order, with no search correctness scoring or
final-test input. Fit-only examples provide its optional demonstrations.
HotpotQA gold answers are included only for the four fit-side proposer examples;
search gold answers do not enter any model prompt. Preparation loads training
tables containing annotation columns; this is not a process-level label sandbox.
Search-side cost responses must not become predictor training records. None has
been used to choose a candidate, tune a method, change a constraint or pick final
units. Token/time summaries and four fixed response-repeat diagnostics are not
held-out task-accuracy results. Explicit split-access controls remain required
before a scientific run.

On 2026-09-26, a primary-source link lookup for `allenai/IFBench_test` returned a
public dataset-card preview containing test prompts and constraint metadata,
in addition to the row count. This was an unintended development-agent exposure,
not a blind-evaluation result. The preview has not been forwarded to a proposer,
predictor, data-preparation input, scorer or inference request. No configuration
was chosen from its contents. The probe configuration had already been fixed.
Subsequent metadata lookups must use the Hub metadata API, not viewer pages.

This exposure must remain disclosed in the final limitations/access audit.
Before a confirmatory freeze, an independent review must check the test-access
boundary. Do not assert completely unexposed developer-held blind data, and do
not silently remove difficult constraints or use observed preview records for
prompt development. If contamination of selection, tuning or final-test results
is found, the charter requires INTEGRITY_BLOCKED.

The pinned IFBench scorer repository was cloned for code/license audit. Its Git
checkout bundles public final-test JSONL files and upstream example/evaluation
responses. Those files were downloaded with the source, but their contents and
scores have not been opened, searched or used by this research. This is not an
air-gapped final-test store. Source inspections must restrict paths to scorer
Python files/README/license; exclude `data/`, `ifbench/data/` and `eval/` from
development searches. The optimizer and predictor must receive explicit sealed
split-access controls before any scientific experiment. Downloading a public
example is not evidence of our model's performance or a permission to tune on it.

## Complete training-side reference component, 2026-09-27

The trusted controller now reads the original fit/search/selection input pools
and hashes their annotation files as bytes for the existing ExecutionIdentity;
it does not interpret those labels or open/hash final leaves. The inference
worker has zero benchmark filesystem read grants and receives complete
input-only search requests by pipe. This is not a claim that the trusted
controller is label-blind or that hashing itself is an air gap.

The original full256 HotpotQA/Qwen reference generation was actually executed;
its first scorer failed before publishing any reference because its code-only
runtime was outside the new worker's existing grant. The failed worker and all
generation costs are retained. An explicit CPU-only recovery uses the same
complete original requests and settled responses, compares unchanged data and
scorer bytes, and lets only the existing search scorer interpret search gold.
No model replay, new data-leaf grant, final access, outcome-selected subsampling
or predictor training from search-side records is authorized by this recovery.
The development agent and document executor inspect aggregate output and the
specific failure traceback, not raw responses, annotations or per-ID scores.

Any resulting seed correctness is a training-side reference, not held-out method
performance, Pilot evidence, native optimizer benefit or ONLINE_PINNED proof.
The earlier public IFBench preview, physical checkout availability and ABI1
limitations remain disclosed above; this component does not erase them or
establish completely unexposed developer-held blind final data.
